# 100일 백테스트 — 브랜치 `backtest_100d`

이 브랜치는 `ssh_upload_stock`(수정본) 위에 **최근 100 거래일 전용 러너**
하나를 더한 것이다. 두 브랜치를 각각 체크아웃해 **동시에** 돌릴 수 있게
분리했다 — 수정본은 SSH 서버에서 실제 파이프라인에 붙여 돌리고, 이쪽은
백테스트만 따로 돌린다.

```
ssh_upload_stock   청산 엔진 + 전 구간 그리드 (파라미터를 정하는 쪽)
       │
       └─► backtest_100d   + run_100d.py (정한 파라미터의 최근 성적을 보는 쪽)
```

---

## 1. 무엇이 다른가

| | `run_exit_backtest` (양쪽 브랜치) | `run_100d` (이 브랜치만) |
|---|---|---|
| 구간 | 시그널 전 구간 | **최근 100 거래일** |
| 목적 | 파라미터 **결정** | 결정한 값의 **최근 성적 확인** |
| 핵심 산출 | 그리드 + walk-forward 표 | 라벨별 성적 + legacy 대비 |
| 표본 | 많을수록 좋음 | 대개 n < 100 (정상) |

> ⚠️ **100일 결과로 파라미터를 고르면 안 된다.** 100 거래일은 시장 국면
> 하나를 겨우 덮는 길이다. 여기서 1등인 설정은 그 국면에 맞춰진 값일 수
> 있다. 파라미터는 전 구간 walk-forward가 정하고, 이 러너는 "그 설정이
> 최근에도 살아 있나"만 본다. 리포트에도 이 경고가 같이 찍힌다.

## 2. 실행

```bash
git checkout backtest_100d

# 실데이터
python -m stock_auto.backtest.run_100d \
    --signals data/tracking/signals.csv \
    --price-dir data/cache

# 구간 바꾸기
python -m stock_auto.backtest.run_100d --signals ... --window 60
python -m stock_auto.backtest.run_100d --signals ... --end 2026-06-30

# 코드만 확인 (데이터 없이)
python -m stock_auto.backtest.run_100d --synthetic
```

산출물은 `experiments/results/`에 떨어진다:

| 파일 | 내용 |
|---|---|
| `backtest_100d.md` | 리포트. 라벨별 분리 + 조언 |
| `trades_100d.csv` | 건별 체결 내역 (MFE/MAE/반사실 포함) |
| `grid_100d.csv` | `--grid` 준 경우에만 |

## 3. 실행 시간 — 실측

4 vCPU 컨테이너, 합성 데이터 기준 실측값이다.

| 시나리오 | 시그널 | 그리드 셀 | 계산 시간 |
|---|---:|---:|---:|
| 100일 · 단순 실행 (그리드 없음) | 523 | 1 | **0.05초 미만** |
| 100일 · 그리드 600셀 | 523 | 600 | **9.1초** |
| 100일 · 50종목 · 그리드 | 1,009 | 600 | **17.3초** |
| 1년 · 그리드 | 1,002 | 600 | **17.5초** |
| 3년 · 50종목 · 그리드 | 5,093 | 600 | **90.2초** |

**비례식**: 대략 `시간 ≈ 시그널 수 × 셀 수 × 30µs`. 선형이라 예측이 쉽다.

### 그래서 실제로 얼마나 걸리나

현재 유니버스(20종목, 하루 3~4건 추천) 기준 100 거래일이면 시그널 300~400건:

| 하려는 것 | 계산 시간 |
|---|---|
| `run_100d` 기본 (그리드 없음) | **1초 미만** |
| `run_100d --grid` (600셀) | **5~8초** |
| `run_exit_backtest --grid` 전 구간 (1년치) | **15~20초** |
| `--with-partial-tp --with-trail-be` (셀 1,800개) | **1~3분** |

**즉 계산은 병목이 아니다.** 실제 체감 시간은 **일봉 다운로드**가 좌우한다:

| 단계 | 첫 실행 | 두 번째부터 |
|---|---|---|
| 일봉 다운로드 (20종목) | **30초 ~ 2분** | **0초** (캐시 적중) |
| 백테스트 계산 | 1~20초 | 1~20초 |
| **합계** | **1~3분** | **10~30초** |

`--price-dir`를 주면 받은 일봉을 CSV로 캐시하므로 두 번째 실행부터는
다운로드가 통째로 빠진다. **처음 한 번만 몇 분 걸리고 그 뒤로는 수십 초**로
생각하면 된다.

네트워크가 막힌 환경이면 `--no-download`로 캐시만 쓰거나, `--synthetic`으로
배선만 확인할 수 있다.

## 4. 리포트에서 볼 순서

1. **0장 판정** — 한 줄 결론과 라벨 간 격차.
2. **2장 라벨별** — 단타/중단기/스윙 각각의 진단과 조치 후보. 이 리포트의 핵심.
3. **3장 legacy 대비** — 현 설정이 D+1 고정%보다 나은가. 같은 구간·같은 시그널 비교.
4. **5장 필터** — 확신도/쿨다운/섹터한도가 무엇을 얼마나 걸렀나.

각 라벨 섹션의 **반사실 표**(배리어 청산 vs D+N 단순보유)를 꼭 본다.
단순보유가 더 좋게 나오면 그 라벨의 청산 규칙이 수익을 깎고 있다는
직접 증거다 — `analysis_2026-09-18.md` §3-1이 쓴 바로 그 계산이다.
