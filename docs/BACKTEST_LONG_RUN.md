# 장기 백테스트 — 1000일 이상

브랜치 `backtest_100d` · 러너 `stock_auto/backtest/run_model_backtest.py`

---

## 1. 왜 러너가 세 개인가 — 시그널 출처의 차이

```
                    시그널 출처            표본 상한
run_exit_backtest   signals.csv 읽기   →  기록된 시그널 이력
run_100d            signals.csv 읽기   →  기록된 시그널 이력
run_model_backtest  모델로 생성        →  ★ 가격 데이터 길이
```

`signals.csv`는 **운영을 시작한 뒤** 쌓인 시그널만 담는다. 2주 운영해서
24건이 쌓였다면, `--window 1000`을 줘도 그 구간 안에 든 시그널은 여전히
24건이다. **표본의 천장이 가격 데이터 길이가 아니라 기록 이력이었다.**

`run_model_backtest`는 과거 일봉에 스코어링 모델을 다시 돌려 "그때 시그널이
났을 것인가"를 재구성한다. 그러면 표본이 가격 데이터가 있는 만큼 늘어난다.

| | 2주 운영 시점 | 1000일 모델 백테스트 |
|---|---:|---:|
| 시그널 | 24건 | **800~1,900건** (종목 수에 비례) |
| 검증 구간(walk-forward 40%) | 10건 미만 | **300~700건** |
| `n ≥ 100` 완료 기준 | ❌ 불가 | ✅ 충족 |

## 2. 실행

```bash
git checkout backtest_100d

# 기본 — 1000 거래일 (약 4년)
python -m stock_auto.backtest.run_model_backtest \
    --days 1000 --price-dir ~/price_cache

# 실제 유니버스를 넣는다 (재현도에 가장 큰 영향)
python -m stock_auto.backtest.run_model_backtest \
    --days 1000 --price-dir ~/price_cache \
    --universe my_universe.csv          # 컬럼: symbol,sector

# 재현도 검증 — 실제 시그널과 대조
python -m stock_auto.backtest.run_model_backtest \
    --days 1000 --price-dir ~/price_cache \
    --validate-against ~/stock_auto/data/tracking/signals.csv

# 더 길게 / 더 짧게
python -m stock_auto.backtest.run_model_backtest --days 2000
python -m stock_auto.backtest.run_model_backtest --days 500 --end 2025-12-31

# 네트워크 막힌 환경에서 배선만 확인
python -m stock_auto.backtest.run_model_backtest --synthetic --days 1000
```

### 데이터 요구량

1000 거래일을 채점하려면 **1000 + 140(지표 워밍업) + 여유 ≈ 1,170봉**,
달력으로 **약 4.6년**의 일봉이 필요하다. `--price-dir`에 그만큼 없으면
러너가 알아서 더 받는다(네트워크 필요).

거래량 컬럼이 **반드시** 있어야 한다. Money 전략 3종이 전부 거래량 기반이고,
문서가 "Money 신호 없이는 매수가 성립하지 않는다"고 못박았다. 거래량 없는
종목은 조용히 0점 처리하지 않고 **명시적으로 제외**하고 경고를 찍는다.

## 3. 실행 시간 — 실측

4 vCPU 컨테이너, 합성 일봉, 그리드 600셀 기준.

| 시나리오 | 시그널 | 생성 | 그리드 | 합계 |
|---|---:|---:|---:|---:|
| 24종목 × 1000일 | 865 | 1.0s | 15.3s | **16.5s** |
| 50종목 × 1000일 | 1,885 | 2.2s | 32.9s | **35.3s** |
| 100종목 × 1000일 | 3,848 | 4.3s | 67.6s | **72.3s** |
| 50종목 × **2000일** | 3,897 | 2.4s | 68.5s | **71.3s** |

**시그널 생성은 병목이 아니다** (1~2초). 시간을 쓰는 건 그리드이고,
`시간 ≈ 시그널 수 × 셀 수 × 30µs`로 선형이다.

### 실제로 얼마나 기다리나

| 하려는 것 | 계산 시간 |
|---|---|
| 1000일 · 24종목 · 그리드 없음 | **2초 미만** |
| 1000일 · 24종목 · 그리드 600셀 | **약 17초** |
| 1000일 · 50종목 · 그리드 600셀 | **약 35초** |
| 1000일 · 100종목 · 그리드 600셀 | **약 72초** |
| 1000일 · 50종목 · `--with-partial-tp --with-trail-be` (5,400셀) | **약 5분** |
| 2000일 · 50종목 · 그리드 600셀 | **약 71초** |

여기에 **첫 실행의 일봉 다운로드**가 붙는다. 1000일은 4.6년치라 100일보다
받을 게 많다:

| | 첫 실행 | 두 번째부터 |
|---|---|---|
| 일봉 다운로드 (24종목 × 4.6년) | **1~4분** | **0초** (캐시) |
| 시그널 생성 + 백테스트 | 17초 | 17초 |
| **합계** | **2~5분** | **약 20초** |

> `--price-dir`를 반드시 준다. 안 주면 매번 4.6년치를 다시 받는다.

## 4. 리포트 읽는 순서

**0장 시그널 생성** — 여기를 먼저 본다. 표본이 제대로 나왔는지 확인하는 곳이다.

```
24종목 · 채점 25,680봉 → 시그널 855건 (발동률 3.33%)
- 매크로 게이트: 지수 ^GSPC, ^IXIC
- 점수 미달로 제외: 24,472봉
- 레짐 게이트 차단: 105봉
- 매크로 게이트 차단: 213봉

| 전략             | 스타일 | 가중치 | 발동 | 비중  |
| MoneyFlowSurge   | 중단기 |   1.5 |  682 | 79.8% |
| IchimokuTrend    | 스윙   |   1.0 |  645 | 75.4% |
```

점검할 것:

| 증상 | 뜻 | 조치 |
|---|---|---|
| 시그널 0건 | 매크로 게이트가 계속 닫혀 있었거나 임계값이 높다 | `--no-macro-gate`로 확인 → `--eff-weak 2.0` |
| 발동률 > 15% | 임계값이 너무 낮거나 유동성 점수가 포화됐다 | `--market` 통화 확인, 유동성 분포 점검 |
| 발동률 < 0.5% | 유니버스가 작거나 데이터가 짧다 | 종목 수·기간 확인 |
| 특정 전략만 100% | 나머지 전략 조건이 안 맞는다 | `docs/MODEL_REPRODUCTION.md` §2 가정 점검 |
| "합성지수로 대체" 경고 | 실제 지수 일봉을 못 받았다 | `^GSPC`, `^IXIC`를 캐시에 넣는다 |

**0장 재현도 검증** (`--validate-against` 준 경우) — 이 백테스트를 얼마나
믿을지 정하는 숫자다. 재현율 50% 미만이면 구조적 결론조차 위태롭다.

그다음은 기존과 같다: **1장 판정 → 3장 라벨별 → 4장 그리드**.

## 5. 무엇을 결론으로 쓸 수 있나

이 백테스트의 시그널은 **재현된 모델**의 산출이다
(`docs/MODEL_REPRODUCTION.md`). 그래서 쓸 수 있는 것과 없는 것이 갈린다.

### ✅ 쓸 수 있다 — 구조적 상대 비교

같은 시그널 집합에 **청산 규칙만 바꿔** 비교하는 것은 유효하다. 시그널이
프로덕션과 조금 달라도 아래 질문의 답은 견딘다:

- 보유상한 1일이 수익을 깎는가? (라벨별 반사실 표)
- 라벨별로 다른 상한이 하나의 상한보다 나은가? (라벨별 그리드)
- ATR 손절이 고정 %보다 나은가?
- 종가 판정이 장중 판정보다 나은가?
- 어느 지평(단타/중단기/스윙)이 구조적으로 불리한가?

이게 `TASK.md` 원칙 2("파라미터는 과거 시그널 전체 백테스트로 결정")가
요구한 바로 그 용도다.

### ❌ 쓸 수 없다

- **절대 수치를 프로덕션 성과 예측으로** — 섹터 게이트·실적 필터가 빠져 있어
  시그널이 프로덕션보다 많다
- **확신도 구간별 분석** — conviction은 LLM 산출이라 소급 재현 불가
- **종목 선정 로직 평가** — 이 모델이 원본과 다를 수 있으므로, 선정이
  좋은지 나쁜지는 이 결과로 판정하지 않는다 (`TASK.md` 원칙 1)

## 6. 재현도를 올리는 순서

영향이 큰 것부터. 자세한 내용은 `docs/MODEL_REPRODUCTION.md` §5.

1. **실제 유니버스** (`--universe`) — 가장 큰 차이 요인
2. **섹터 게이트** — 섹터 ETF 일봉 + 게이트 구현
3. **실적 필터** — 실적 일정 데이터
4. **VAI·유동성 산식** — 원본 수치를 알려 주면 맞춘다

가장 빠른 길은 **원본 `indicators_v2.py` / `strategies.py`를 이 저장소에
올리는 것**이다. 그러면 재현이 아니라 원본을 그대로 쓸 수 있고, 가정
14개가 전부 사라진다.
