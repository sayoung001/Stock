# 스코어링 모델 재현 — 가정 목록과 한계

작성 2026-09-19 · 대상 `stock_auto/model/`

---

## 0. 왜 재현했는가

백테스트가 `data/tracking/signals.csv`를 **읽고** 있었다. 그 파일에는 운영
시작 뒤 쌓인 시그널만 있어서, 2주치(24건)뿐이면 `--window 1000`을 줘도
볼 수 있는 시그널은 24건이 전부였다. **표본의 천장이 가격 데이터 길이가
아니라 기록된 시그널 이력이었다.**

그 천장을 없애려면 과거 일봉에 스코어링 모델을 다시 돌려 "그때 시그널이
났을 것인가"를 재구성해야 한다. 그런데 스코어링 원본(`stock_auto/`
51개 모듈)이 이 저장소에 없다(`codemap_exit.md` §0). 그래서
`현재_적용_로직_전수.md` §2.3~2.8의 명세를 읽고 **다시 구현했다.**

`US_KR_CLAUD_분석_및_발전방향.md` §3.5가 지적한 "백테스트 엔진 부재 →
모든 가중치·임계값이 미검증 가정치" 문제의 그 엔진이다.

## 2. 세운 **가정** (문서에 값이 없던 것)

| # | 항목 | 가정 | 왜 이렇게 |
|---|---|---|---|
| **A1** | VAI 2단 정의 | `stage1 = vol_ma5 / vol_ma20.shift(1)`, `stage2 = vol_ma20 / vol_ma60.shift(1)` | 문서는 "거래량 가속·지속"이라고만 씀. 단기/중기 비율이 가장 자연스러운 해석이고 컷 4개(1.5/1.2/2.0/1.1)와 맞아떨어진다 |
| **A2** | `vai_sustained` / `vai_spike_only` | sustained = stage1≥1.5 ∧ stage2≥1.2 · spike_only = stage1≥2.0 ∧ stage2<1.1 | §7.1의 네 숫자를 이 조합으로 읽었다 |
| **A3** | 유동성 sigmoid 기울기 | 반감폭 = 반 decade (약 3.2배) | 범위(0.3~1.4)와 중심($50M)만 있고 기울기가 없다. 중심에서 0.85가 나와 `유동성≥0.7` 조건과 정합적 |
| **A4** | 거래대금 기준 | 5일 평균 (`trading_value.rolling(5)`) | 문서가 "5일 평균 거래대금 ≥ $2M" 사전필터를 언급 → 같은 창 사용 |
| **A5** | PullbackBuy "EMA20 터치 후 회복" | 저가 ≤ EMA20 × 1.01 ∧ 종가 > EMA20 | "터치"의 허용폭이 없다. 1%로 잡았다 |
| **A6** | 매크로 지수 | `^GSPC`, `^IXIC`. 없으면 **유니버스 동일가중 합성지수** | 실제 지수 심볼이 명시되지 않았다. 합성 폴백은 유니버스가 편향되면 지수 대용이 못 된다 (§4 한계) |
| **A7** | 섹터 게이트 | **비활성** | 섹터 ETF 12개 일봉 + `compute_sector_status()` 로직이 필요. 원본이 없어 재현 불가. 결과적으로 프로덕션보다 시그널이 **조금 더 많이** 나온다 |
| **A8** | 보유기간 라벨 | 발동 전략의 **스타일 가중합 최대**, 동점 시 긴 지평 | 프로덕션은 LLM(PortfolioAgent)이 붙인다. 소급 재현 불가 → 문서가 전략마다 명시한 스타일로 대체 |
| **A9** | 확신도(conviction) | **기록하지 않는다 (NaN)** | LLM 산출값이라 소급 불가. 없는 값을 지어내면 확신도 필터가 가짜 숫자로 작동한다. `--confidence-proxy`로 점수 유도 대용값을 쓸 수 있지만 **같은 값이 아니다** |
| **A10** | 종목 레짐 5단계 경계 | MA 배열 기반 (아래 표) | 문서가 "5단계(0~4)"라고만 씀 |
| **A11** | Bearish_Div | 종가가 20일 신고가인데 RSI는 20일 최고치 미달 | 문서에 산식 없음 |
| **A12** | 유니버스 | 24종목 추정 (analysis 문서 등장 종목 12개 + 섹터 분산용 12개) | `US_SAMPLE` 20종목의 실제 목록이 문서에 없다. `--universe`로 덮어써야 한다 |

## 3. 누출 차단 — 이 코드를 믿을 근거

모든 지표가 **절단 불변(truncation invariance)** 검사를 통과한다.

> i번째 봉의 값이 0..i 봉만 쓴다면, 데이터를 i에서 잘라 다시 계산해도
> i번째 값은 똑같아야 한다. 하나라도 달라지면 미래를 봤다는 뜻이다.

`tests/test_model_leakage.py`가 지표 35종 × 절단점 4곳, 전략 10종 ×
절단점 3곳, 점수·레짐, 그리고 **시그널 목록 전체**에 대해 이를 검증한다.
과거 candle_idx 오프바이원 사고(CLAUDE.md 교훈 2)가 정확히 이 검사로
잡히는 종류의 버그다.

특별히 주의한 두 곳:

| 위치 | 함정 | 처리 |
|---|---|---|
| `break_high20` | 당일 고가가 포함된 20일 최고가와 종가를 비교하면 자기참조 | `high20.shift(1)`과 비교 |
| `SqueezeBreakout` | 당일 스퀴즈 상태를 조건에 쓰면 "해제" 판정이 자기참조 | `squeeze_on.rolling(5).sum().shift(1)` |
| 일목 선행스팬 | 원 정의는 26봉 **앞으로** 미는 것 | 백테스트에선 26봉 **전** 값이 지금의 구름 → `shift(+26)` (과거 참조, 누출 아님) |

전략 10종 전부 **죽은 코드가 아님**도 검증한다
(`test_every_strategy_can_fire`). 조건 모순으로 영원히 발동하지 않는
전략이 있으면 그 스타일의 라벨이 통째로 사라져 백테스트가 조용히 편향된다.

## 4. 한계 — 이 결과로 **하면 안 되는 것**

### ❌ 절대 수치를 프로덕션 성과로 읽기

A7(섹터 게이트 없음) · A13(실적 필터 없음)만으로도 이 모델은 프로덕션보다
시그널을 **더 많이** 낸다. A12(유니버스 추정)가 다르면 종목 구성 자체가
다르다. PF·기대값의 절대값은 프로덕션 예측치가 아니다.

### ❌ 확신도 구간별 분석

A9. 확신도를 기록하지 않으므로 그 표는 비어 있다. `--confidence-proxy`를
켜면 채워지지만, 그 값은 기술 점수의 단조 변환이라 **LLM conviction과
다른 물건**이다. `analysis_2026-09-18.md` §3-3의 "확신도 변별력" 질문은
이 백테스트로 답할 수 없다.

### ✅ 쓸 수 있는 것 — 구조적 결론

같은 시그널 집합에 **청산 규칙만 바꿔 가며** 비교하는 것은 유효하다.
시그널이 프로덕션과 조금 달라도, "보유상한 1일이 수익을 깎는가",
"라벨별로 다른 상한이 나은가", "ATR 손절이 고정 %보다 나은가" 같은
**상대 비교**는 견딘다. 이번 작업의 목적이 바로 그것이다
(`TASK.md` 원칙 2: "파라미터는 과거 시그널 전체 백테스트로 결정").

## 5. 재현도를 숫자로 확인하는 방법

```bash
python -m stock_auto.backtest.run_model_backtest \
    --days 1000 --price-dir data/cache \
    --validate-against data/tracking/signals.csv
```

겹치는 구간에서 (종목, 날짜) 쌍이 얼마나 일치하는지 센다.

| 지표 | 뜻 |
|---|---|
| **재현율** | 실제 시그널 중 모델이 잡아낸 비율 |
| **정밀도** | 모델 시그널 중 실제로도 났던 비율 |

- **재현율 ≥ 50%** → 구조적 결론(어느 지평이 불리한가 등)은 끌어낼 만하다
- **재현율 < 50%** → 유니버스·임계값·지표 정의 중 하나가 원본과 다르다.
  §2의 가정을 순서대로 점검한다. 이 상태의 결과는 프로덕션 성과의 대용이 아니다

재현율을 올리는 순서 (영향이 큰 것부터):

1. **A12 유니버스** — `--universe`로 실제 20종목을 넣는다. 가장 큰 차이 요인
2. **A7 섹터 게이트** — 섹터 ETF 일봉을 캐시에 넣고 게이트를 켠다 (구현 필요)
3. **A13 실적 필터** — 실적 일정을 넣는다 (구현 필요)
4. **A1~A3 VAI·유동성** — 원본 산식을 알려 주면 맞춘다

가장 빠른 길은 **원본 `indicators_v2.py` / `strategies.py`를 이 저장소에
올리는 것**이다. 그러면 재현이 아니라 원본을 그대로 쓸 수 있고, 이 문서의
가정 14개가 전부 필요 없어진다.
